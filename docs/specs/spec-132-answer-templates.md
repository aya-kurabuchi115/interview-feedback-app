## 1. 概要

### 1.1 背景

質問データベース（`src/lib/questions/data.ts`）には既に `exampleAnswer` と `tips` フィールドが存在し、質問詳細ページ（`/questions/[id]`）では模範解答と回答のポイントが表示されている。しかし、現在の実装ではユーザーが自分の回答を練習・比較する機能がなく、STAR法やPREP法などの回答フレームワークガイドも提供されていない。

### 1.2 ゴール

- 既存の質問データ（`exampleAnswer`, `tips`）を活用しつつ、ユーザーが自分の回答を入力・比較できる UI を構築する
- STAR法・PREP法・起承転結法のフレームワークガイドを提供する
- 業界別の回答トーン・キーワード提案を表示する
- ユーザーの回答を `localStorage` に自動保存し、再訪時に復元する

### 1.3 スコープ外

- AI による回答のリアルタイム添削（Claude API との連携は別 Issue）
- ユーザー回答のサーバーサイド保存（DB 保存は別 Issue）
- 質問データベースの質問追加・編集（既存の `data.ts` の内容は変更しない）
- `docs/specs/spec-questions.md` で保護されている面接質問集の構造・データの変更

## 2. ユーザーストーリー

As a 就活生, I want 面接質問に対する模範解答やテンプレートを参照できる so that 自分の回答の構成を改善できる.

## 3. 機能要件

### 3.1 基本フロー

1. ユーザーが質問詳細ページ（`/questions/[id]`）にアクセスする
2. 模範解答がアコーディオン（初期状態: 折りたたみ）で表示される
3. ユーザーがフレームワークガイド（STAR法 / PREP法 / 起承転結法）をタブで切り替えて参照する
4. ユーザーが自分の回答をテキストエリアに入力する
5. 入力した回答が `localStorage` に自動保存される
6. 「比較する」ボタンをクリックすると、自分の回答と模範解答のサイドバイサイド比較が表示される
7. 業界別のキーワード提案が質問の `industry` フィールドに基づいて表示される

### 3.2 代替フロー

- `exampleAnswer` が空文字の質問: 「模範解答は準備中です」と表示する
- ユーザーの回答が未入力の状態で比較ボタンをクリック: 「まず自分の回答を入力してください」と表示する
- モバイル端末でのアクセス: サイドバイサイド比較を上下配置（スタック）に切り替える

### 3.3 エラーフロー

- ユーザーの回答入力が 5000 文字を超えた場合: バリデーションエラー「回答は5000文字以内で入力してください」を表示する
- `localStorage` 容量超過時: `try-catch` でエラーをキャッチし、コンソールにのみログ出力（ユーザーには表示しない）
- 質問 ID が存在しない場合: 既存の `notFound()` 処理が発動し 404 ページを表示する

## 4. 受け入れ基準

- [ ] 質問詳細ページに模範解答を展開可能なアコーディオンとして表示（初期状態: 折りたたみ）
- [ ] STAR法・PREP法・起承転結法のフレームワークガイドをタブコンポーネントで実装
- [ ] 自分の回答を入力できるテキストエリアが表示される
- [ ] 自分の回答と模範解答のサイドバイサイド比較表示機能が動作する
- [ ] 業界別の回答トーン・キーワード提案が表示される
- [ ] モバイルレスポンシブ対応済み（サイドバイサイドはモバイルで上下配置に切り替え）
- [ ] `exampleAnswer` が空文字の質問では「模範解答は準備中です」と表示される
- [ ] ユーザーの回答入力が 5000 文字を超えた場合にバリデーションエラーを表示する

### 5.5 フレームワークガイドの内容

#### STAR法
| ステップ | 説明 | テンプレート |
|----------|------|-------------|
| Situation | 状況の説明 | 「私は大学○年の時に、○○の場面がありました。」 |
| Task | 与えられた課題 | 「その中で私の役割は○○でした。」 |
| Action | 取った行動 | 「そこで私は○○を実行しました。」 |
| Result | 結果と学び | 「その結果、○○を達成し、○○を学びました。」 |

#### PREP法
| ステップ | 説明 | テンプレート |
|----------|------|-------------|
| Point | 結論 | 「私の強みは○○です。」 |
| Reason | 理由 | 「なぜなら○○だからです。」 |
| Example | 具体例 | 「例えば、○○の経験があります。」 |
| Point | 結論の再提示 | 「このように○○の力を御社でも活かしたいと考えています。」 |

#### 起承転結法
| ステップ | 説明 | テンプレート |
|----------|------|-------------|
| 起 | 導入・背景 | 「○○について、私の経験をお話しします。」 |
| 承 | 展開・詳細 | 「具体的には、○○に取り組みました。」 |
| 転 | 転換・困難 | 「その中で○○という課題に直面しました。」 |
| 結 | 結論・学び | 「この経験から○○を学び、御社でも活かしたいです。」 |

## 8. リスクと緩和策

| リスク | 影響度 | 緩和策 |
|--------|--------|--------|
| `localStorage` の容量制限（通常 5MB） | 低 | 1回答あたり最大 5000 文字で容量超過の可能性は極めて低い。超過時は `try-catch` でグレースフル処理 |
| 質問データの `exampleAnswer` が空の質問が多い場合 | 中 | 「準備中」メッセージを表示し、将来的にデータ拡充で対応 |
| Client Component 化による SSR メリットの低下 | 低 | 回答入力・比較部分のみ Client Component とし、模範解答表示やフレームワークガイドは Server Component のまま維持 |
| 既存の質問詳細ページのレイアウト崩れ | 中 | 既存の 2 カラムレイアウト（lg:grid-cols-3）を維持しつつ、メインコンテンツ（lg:col-span-2）内に新コンポーネントを追加 |
